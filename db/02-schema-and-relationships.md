# 2. Schema and relationships

The authoritative application schema is [`backend/prisma/schema.prisma`](../backend/prisma/schema.prisma). The initial SQL migration is [`backend/prisma/migrations/20261121204819_init/migration.sql`](../backend/prisma/migrations/20261121204819_init/migration.sql).

| Entity/table | Primary key | Important attributes | Foreign key / relationship |
|---|---|---|---|
| `users` | `id` UUID text | name, unique email, password hash, role enum, createdAt | One user owns many chat sessions |
| `equipment` | `id` UUID text | unique name, optional description | One equipment type has many tests |
| `tests` | `id` UUID text | name, aliases[], steps[], limits, safety[], tools[], standard, troubleshooting | `equipmentId` → `equipment.id`, `ON DELETE CASCADE` |
| `documents` | `id` UUID text | title, filePath, equipmentType, standard, status enum, uploadedAt | One document has many chunks |
| `document_chunks` | `id` UUID text | content, page, equipmentType, testName, standard, optional vector(768) | `documentId` → `documents.id`, `ON DELETE CASCADE` |
| `chat_sessions` | `id` UUID text | title, createdAt | `userId` → `users.id`, `ON DELETE CASCADE` |
| `messages` | `id` UUID text | role enum, content, optional JSON sources, createdAt | `sessionId` → `chat_sessions.id`, `ON DELETE CASCADE` |

## Cardinalities

- `users 1 ── 0..many chat_sessions`
- `chat_sessions 1 ── 0..many messages`
- `equipment 1 ── 0..many tests`
- `documents 1 ── 0..many document_chunks`
- There is no 1:1 or many-to-many relationship in the current requirements. Therefore, there is no many-to-many junction table.

All entity IDs are UUID strings. Required Prisma fields become `NOT NULL`; IDs are generated by Prisma. Database unique constraints exist on `users.email` and `equipment.name`. `Role`, `DocumentStatus`, and `MessageRole` are PostgreSQL enums.
